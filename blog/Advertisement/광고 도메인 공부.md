-> 병렬 브로드 캐스팅에 대해서 공부하기
-> 이때, 어떻게 계속 연결되어있는거지? PUB/SUB 관점인가?

> [!ANSWER] 병렬 브로드캐스팅과 커넥션 유지에 대해
> - **Pub/Sub 아님.** "브로드캐스팅"이라는 표현 때문에 하나의 메시지를 뿌리는 것처럼 보이지만, 실제로는 각 DSP 로 **N 개의 독립적인 HTTP request/response** 가 병렬로 나가는 구조다.
> - **왜 Pub/Sub 가 아닌가?** Pub/Sub 는 발행하고 잊어버리는(fire-and-forget) 비동기 모델이라 응답을 기다리지 않는다. 하지만 RTB 는 "경매"라서 반드시 각 DSP 의 응답(입찰가)을 정해진 시간 안에 받아야 낙찰자를 정할 수 있다. 즉 **동기적 request/response** 가 본질이다.
> - **"어떻게 계속 연결되어 있나?"** 매 경매마다 TCP 연결을 새로 맺으면(핸드셰이크) 너무 느리다. 그래서 **HTTP Keep-Alive(Persistent Connection)** 로 SSP↔DSP 간 커넥션을 미리 열어두고 재사용한다.
> - 실무에서는 각 DSP 마다 **커넥션 풀(Connection Pool)** 을 유지해서, 경매가 발생할 때마다 풀에서 열린 커넥션을 꺼내 즉시 요청을 보낸다. 이게 "계속 연결되어 있다"의 정체다. (요즘은 HTTP/2 멀티플렉싱을 쓰기도 함)

> [!ANSWER] "병렬 브로드캐스팅" 동작 원리 (심화)
> **1. "브로드캐스팅"의 의미**
> - 진짜 1:N 단일 전송(방송)이 아니라, DSP 가 100개면 **100개의 독립적인 HTTP POST 요청**을 각각 따로 만들어 보낸다. "모든 DSP 에게 동시에 알린다"는 뜻일 뿐이다.
>
> **2. 왜 순차(sequential)가 아니라 병렬(parallel)인가 — 시간 제약**
> - 순차로 보내면: DSP1 요청 → 100ms 대기 → DSP2 요청 → 100ms 대기 → ... 100개면 **총 10초** → 경매 timeout(수백 ms) 초과, 불가능.
> - 병렬로 보내면: 100개를 **동시에 발사**하므로 전체 소요 시간이 "가장 느린 하나의 응답 시간"(~100ms)에 수렴한다. DSP 수가 늘어도 전체 시간은 거의 그대로.
>
> **3. 어떻게 "동시에" 쏘는가 (구현 관점)**
> - **비동기 I/O**: 응답 대기 중 스레드를 붙잡지 않고 다른 요청을 계속 발사. (Go goroutine, Node 이벤트 루프, Java NIO 등)
> - **커넥션 풀 재사용**: Keep-Alive 커넥션을 미리 열어둬 매번 TCP 핸드셰이크를 생략.
> - **Fan-out / Fan-in 패턴**:
> 	- *Fan-out*: 하나의 Bid Request 를 N 개 DSP 로 퍼뜨리는 단계
> 	- *Fan-in*: 흩어진 응답을 다시 모아 경매를 여는 단계
> 	- timeout 이 되면 fan-in 을 강제 종료하고, 그때까지 모인 응답만으로 경매 마감.
>
> **4. Go 로 개념 표현 ([[Golang]] 관점)**
> ```go
> results := make(chan BidResponse, len(dsps))
> ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
> defer cancel()
>
> for _, dsp := range dsps {
>     go func(d DSP) {              // fan-out: 각 DSP를 goroutine으로 동시 발사
>         resp := d.SendBidRequest(ctx, req)
>         results <- resp
>     }(dsp)
> }
>
> // fan-in: timeout 안에 도착한 응답만 수집
> var bids []BidResponse
> for {
>     select {
>     case r := <-results:
>         bids = append(bids, r)
>     case <-ctx.Done():           // 100ms 지나면 경매 마감
>         runAuction(bids)
>         return
>     }
> }
> ```
> **한 줄 요약**: 병렬 브로드캐스팅 = N 개 DSP 에게 개별 HTTP 요청을 동시에(비동기 I/O + 커넥션 풀) 발사(fan-out)하고, timeout 안에 돌아온 응답만 모아(fan-in) 경매를 여는 것.

	- Timeout 기준은 어떻게 정하는걸까?
	- 몇 초 기준이 제일 안전한 입찰 과정일까?

> [!ANSWER] Timeout 기준에 대해
> - **초가 아니라 밀리초(ms) 단위다.** 사용자가 페이지를 열고 광고가 뜨기까지 사람이 체감하지 못하는 시간 안에 경매 전체가 끝나야 한다.
> - **경매 전체 timeout**: 보통 100~300ms 수준.
> - **DSP 개별 timeout**: 그 안에서 각 DSP 에게 주는 시간은 더 짧아 **보통 100~120ms**. Google(Authorized Buyers) 표준이 대략 120ms.
> - **왜 이렇게 빡빡한가?** SSP 는 가장 느린 DSP 를 무한정 기다릴 수 없다. timeout 이 지나면 그때까지 도착한 응답들만으로 경매를 마감하고, **늦게 온 입찰은 응답해도 폐기**된다.
> - 그래서 "몇 초"가 정답이 아니라, 네트워크 지연(RTT)을 뺀 나머지 안에서 DSP 가 연산을 끝낼 수 있는 최대치 = **대략 100ms 내외**가 업계 표준이다.
> - 트레이드오프: SSP 가 timeout 을 길게 잡으면 더 많은 입찰을 받아 수익이 오르지만, 페이지 로딩이 느려져 UX 가 나빠진다. 그 균형점이 100~200ms.

경매에서 이기는 기준은 어떻게 되는걸까?

> [!ANSWER] 경매에서 이기는 기준에 대해
> 기본 원칙은 **가장 높은 입찰가를 낸 DSP 가 승리**. 다만 실무에는 층위가 더 있다.
> 1. **floor price(최저 입찰가) 통과** — SSP/매체가 정한 최소 가격을 넘지 못하면 1등이어도 낙찰 불가. (노트 앞부분의 "최소 입찰가")
> 2. **랭킹은 단순 최고가가 전부가 아님** — 매체는 아래 요소로 입찰을 정렬한다.
> 	- **광고 품질/관련성**: 사용자에게 안 맞는 광고는 클릭이 안 되어 장기 수익에 해로움
> 	- **eCPM(유효 CPM) 환산 비교**: 과금 방식(CPC, CPM 등)이 달라도 1000회 노출당 기대수익으로 환산해 공정하게 비교
> 	- **정책/브랜드 안전성**: 금지 카테고리(성인, 도박 등)는 가격과 무관하게 탈락
> 3. **최고가 낙찰 -> 지불**: First-Price 면 부른 값 그대로, Second-Price 면 2등 금액 + $0.01
> - 정리: **floor price 통과 -> eCPM/품질로 랭킹 -> 최고가 낙찰 -> 방식에 따라 지불**

Auction Dynamics
- Second-Price Auction
	- 1등이 **2등 금액 + 0.01달러** 를 지불하는 방식 (자기가 부른 금액이 아니라 2등 가격 기준)
	- 예) 1등 5달러, 2등 3달러 -> 1등은 3.01달러만 지불
- First-Price Auction
	- 제시한 금액을 그대로 지불하는 형태로 이어짐
	- 최근 업계는 대부분 First-Price 로 전환됨 (Google 도 2019년 전환). Second-Price 는 헤더 비딩 등 다단계 경매에서 투명성 문제가 있었기 때문

### 모르는 용어들
- **Media Mix ( 매체 믹스 )**
	- 하나의 광고 캠페인에서 여러 매체/채널(검색, 디스플레이, SNS, 동영상, TV 등)에 **예산을 어떻게 배분할지 조합하는 전략**.
	- 목표는 한정된 예산으로 최대 효과(도달, 전환)를 내는 것. "어느 채널에 얼마를 넣어야 ROI 가 가장 좋은가"를 다룬다.
	- 이를 데이터로 분석해 최적 배분을 찾는 걸 **MMM(Media Mix Modeling)** 이라고 부른다.
- **A/B 테스트**
	- 두 가지 버전(A안, B안)을 동시에 노출하고 **어느 쪽 성과(클릭률, 전환율 등)가 더 좋은지 통계적으로 비교**하는 실험 방법.
	- 광고에서는 소재(카피, 이미지), 타겟팅, 랜딩 페이지 등을 A/B 로 나눠 테스트한다.
	- 핵심은 **하나의 변수만 바꿔서** 비교해야 원인을 정확히 알 수 있다는 점.
- **RTB ( Real Time Bidding - 실시간 경매 )**
	- 위에서 정리한 내용대로, 사용자가 페이지를 여는 순간(수백 ms 안에) 지면(Inventory)을 놓고 여러 DSP 가 실시간으로 입찰해 낙찰자를 정하는 방식.
